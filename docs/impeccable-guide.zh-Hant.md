# 用 Impeccable 製作有質感的網站：Codex 實用手冊

適用對象：使用 macOS、Codex 桌面程式，想把已有網站做得更專業、更易用的使用者。

本文依據本專案已安裝的 **Impeccable 4.8.0** 撰寫；引擎版本為 **0.1.18**。範例以你的美股研究網站 Northstar 為主。這份手冊介紹操作方法，本次沒有替網站重新設計，也沒有把尚未接上的行情或分析服務描述為可用。

正式網站入口：[https://angusqaq.github.io/stock-website/](https://angusqaq.github.io/stock-website/)。設計修改先在本機預覽，驗收後再更新這個網址。

## 1. 先理解 Impeccable 負責什麼

Impeccable 提供一套設計語言、工作流程、參考資料與檢查工具，讓 Codex 能更具體地處理排版、資訊層級、色彩、互動、文案和可用性。它需要配合 Codex 讀取你的程式碼、理解產品與執行修改。

金融工作台的質感，主要來自以下幾件事：

- **一眼可讀**：使用者能迅速找到股票、價格、報價時間、現金與風險。
- **層級明確**：股價、盈虧、標籤和說明文字，各有適當的視覺重量。
- **規則一致**：相同按鈕、輸入框、表格、邊距及數字格式，在每個頁面都一致。
- **狀態可靠**：載入、休市、延遲、斷線和資料不足，都有準確的表示。
- **操作完整**：鍵盤、手機、表單驗證、錯誤復原和長內容都能正常使用。

Impeccable 可以改善這些體驗。行情來源、持倉資料庫、富途費率、Codex 訂閱授權及投資計算，仍需相應的資料、後端與測試。

## 3. 分清楚兩個輸入位置

這是最容易混淆的地方。以下兩種指令有不同用途：

| 輸入位置 | 範例 | 用途 |
|---|---|---|
| **Codex 聊天輸入框** | `$impeccable critique 股票詳情頁` | 讓 Codex 使用設計工作流程，讀取、評估或修改網站 |
| **Terminal** | `npx --no-install impeccable detect src/` | 執行工具安裝、版本檢查或確定性的程式掃描 |

在 Codex 中，請使用 `$impeccable`。其他編輯器的教學可能使用 `/impeccable`，那是不同客戶端的入口。

`critique`、`polish`、`layout` 等設計工作，請在聊天中提出。Terminal 的 detector 不會自行替你完成一份 AI 設計改版。

## 4. 第一次在 Mac 使用：照這個順序

### 4.1 同步專案

在 Codex 桌面程式開啟你平常使用的 `stock-website` 專案資料夾，確認它是連到 `angusQAQ/stock-website` 的同一份倉庫。

Terminal 進入該資料夾：

```bash
cd /你的專案路徑/stock-website
git status --short
```

如果有尚未保存的修改，先妥善保存與提交。工作目錄乾淨後，再同步遠端，例如：

```bash
git pull --ff-only
npm ci
npx --no-install impeccable --version
```

最後一行應顯示 `4.8.0`。若找不到 `npm`，先安裝 Node.js；本網站需要 Node 22 以上，本次驗證使用 Node 24。

### 4.2 重新探索 skills

在 Codex 桌面程式重新開啟專案的新工作階段，輸入 `$impeccable`，或到技能清單搜尋 Impeccable。已經開著的聊天不一定會立即重新探索新安裝的技能。

本專案已把 skill 納入 Git，通常同步倉庫即可取得。要在其他新專案安裝，使用官方流程：

```bash
npx impeccable install --providers=codex --scope=project
```

安裝器可能詢問是否加入設計 hook。它會在代理修改 UI 檔案後提供品質提醒。Codex 首次載入專案 hook 時，依客戶端提示到 `/hooks` 檢查並核准；不同桌面版本的入口可能略有差異。安裝檔案存在與 hook 已獲客戶端信任，是兩個不同狀態。

### 4.3 開啟可預覽的本機網站

在第一個 Terminal：

```bash
npm run build
npm run db:local
npm run dev:api
```

這會提供本機 Worker 與測試用本機資料庫。接著另開第二個 Terminal：

```bash
npm run dev
```

第二個 Terminal 顯示的 Vite 網址就是設計時的預覽入口，預設通常是 `http://localhost:5173`；請以實際輸出為準。保留這兩個 Terminal，讓介面與 API 在你操作時持續執行。

雲端 API 尚未連接時，正式 Pages 會顯示對應狀態。本機開發資料庫與正式雲端帳本分開，不要把測試資料當成真實資產，也不要把個人資料檔提交到 Git。

## 5. 讓 Codex 理解你的產品與設計

Impeccable 主要使用兩份長期文件：

| 文件 | 回答的問題 | 應包含的內容 |
|---|---|---|
| `PRODUCT.md` | 網站服務誰、解決什麼問題？ | 使用者、核心流程、能力、約束、真實資料與尚未決定的事項 |
| `DESIGN.md` | 這個網站如何呈現？ | 色彩、字級、間距、版面、元件與狀態規範 |

你已有網站，適合先建立產品背景，再記錄現有視覺系統。兩份文件都應保留在 Git，避免每次改一頁就換一套風格。

### 第一步：建立產品背景

貼到 **Codex 聊天**：

```text
$impeccable init

這是我的個人美股研究工作台 Northstar。
請先讀 AGENTS.md、docs/product-requirements.md 和現有程式碼，沿用已確認的需求。
主要流程是查股票、選投資期間、閱讀分析、查看美元持倉及記錄交易。
介面需接近證券公司平台，資訊密集，分析報告則先呈現結論、理由和風險。
請把可從現有文件確認的事實寫入 PRODUCT.md，只詢問文件中缺少且影響設計的資訊。
```

`init` 主要整理產品背景，不負責決定新的視覺風格。涉及本金、帳戶或憑證時，使用資料類型與需求描述即可，不要把真實值寫進產品文件。

### 第二步：記錄現有設計

貼到 **Codex 聊天**：

```text
$impeccable document

請根據 src/styles.css、目前的 React 元件與本機畫面，整理現有設計系統到 DESIGN.md。
保留深色證券工作台方向，記錄色彩、資訊層級、數字格式、表格、按鈕、表單與響應式規則。
把已存在的規則與建議改善項目分清楚，避免把尚未實作的設計寫成現況。
```

若已有 `DESIGN.md`，先決定要更新哪些內容，再執行整理。工具可能會詢問採用合併、更新或覆寫；先看差異，保留有用的既有規則。

### 對你的網站，最重要的背景

- 這是一個用來完成工作與判斷的介面，屬於 Impeccable 的 **Operate** 模式。
- 密集行情與表格要有清楚分組、數字對齊、可讀字級和穩定的互動位置。
- 綠／紅涉及市場漲跌語意，應在各頁保持一致。
- 來源時間、盤前盤後、延遲及缺漏屬於功能資訊，需要真實表示。
- 私人使用、公開網站、雲端儲存和存取控制要分開描述。

品牌行銷頁會更重視說服與視覺表達；你的核心工作台應優先支援快速閱讀和準確操作。

### 一組可討論的視覺起點

以下可作為與 Codex 討論的起始提案，確認後再納入 DESIGN.md。實際數值應配合內容長度、顯示密度及手機閱讀測試調整。

| 項目 | 起始提案 | 判斷重點 |
|---|---|---|
| 主要股價 | 約 32–40px，使用等寬數字配置 | 更新時小數位不跳動，價格易讀 |
| 區塊標題 | 約 18–22px | 區分報價、圖表、持倉及分析 |
| 說明與分析正文 | 約 14–16px，適當行高 | 繁體中文長文能連續閱讀 |
| 表格與功能標籤 | 約 12–14px 起評估 | 密集資訊仍能辨認，關鍵數據不靠極小字體 |
| 手機輸入欄位 | 約 16px 起評估 | 避免為了版面壓縮而犧牲輸入可讀性 |
| 間距 | 4、8、12、16、24、32px 的少量級距 | 相關資訊靠近，區塊之間明確分開 |
| 色彩 | 深色底、兩級表面色、主要操作色、漲跌色 | 色彩有用途，次要文字仍有足夠對比 |
| 數字格式 | 金額、百分比、股數各有一致規則 | 負號、幣別、小數位與缺值表示固定 |

給 Codex 的決策依據應是「改完更容易完成什麼任務」。例如把漲跌數字與來源時間放在同一個視覺群組，讓使用者比較價格時也能確認新鮮度；這比單純指定更多陰影與裝飾更容易驗收。

## 6. 改善已有網站的完整流程

建議順序：

1. **建立背景**：`init` 與 `document`。
2. **看整體體驗**：`critique`。
3. **查技術品質**：`audit`。
4. **選一個範圍改善**：例如 `typeset` 或 `layout`。
5. **處理不同尺寸**：`adapt`。
6. **補狀態與邊界**：`harden`。
7. **完成最後打磨**：`polish`。
8. **實際驗收與發布**：操作、測試、建置、Git commit、部署。

第一次建議從「股票詳情頁」或「交易記錄視窗」開始。一次處理一個主要區域，更容易比較成效與回復修改。

### 6.1 先請它評估整體體驗

```text
$impeccable critique src/App.tsx 的股票詳情工作台

目標使用者會快速查看股價、漲跌、來源時間、K 線與分析入口。
請使用本機預覽檢查桌面與手機，先提供改善報告及優先順序。
這一輪以評估為交付，列出最值得先處理的三項問題、具體位置與理由。
```

`critique` 關注資訊層級、理解成本、產品特性與操作體驗。本版在可用時採用獨立代理分別評估，Codex 可能先詢問是否允許這次使用多代理。若你只想單一代理，可直接說明；報告應交代採用的方式，不能把降級評估當成完整獨立評估。

### 6.2 再請它檢查可驗證的品質

```text
$impeccable audit src/TransactionModal.tsx

請檢查標籤、鍵盤操作、焦點管理、錯誤訊息、手機尺寸與字體放大。
先列出 P0 到 P3 的問題，附上重現方式和可用的證據，再建議修正順序。
```

`audit` 的主要交付是技術品質報告。它與設計喜好的評估不同，也不應把 detector 的單一提示直接當成已證實的缺陷。

### 6.3 只處理選定的問題

假設你選擇改善「重要價格與說明文字層級」：

```text
$impeccable typeset 股票詳情頁的報價區及分析摘要

目標：主要價格、漲跌、時間與摘要更容易掃讀。
範圍：只調整字級、字重、行高、數字對齊與文字間距。
保留：深色視覺方向、目前功能、投資文字、資料來源與金額計算。
驗收：桌面與 390px 手機可讀，200% 放大時重要操作仍可使用。
完成後說明修改檔案、改善理由及驗證結果。
```

完成一輪後，先看本機畫面與差異，再進下一輪。

## 7. 從零建立新頁面的流程

新增頁面適合先把任務與資訊架構想清楚：

```text
$impeccable shape 我的美元資產頁

使用者要查看可用美元、持倉市值、成本、損益和交易紀錄，並可記錄入金與買賣。
請先提出資訊優先順序、桌面與手機的區塊安排，以及主要操作路徑。
沿用現有 Northstar 設計方向，清楚標示需要我決定的產品問題。
```

方向確認後，明確交代開始實作的範圍：

```text
請依剛才確認的方案實作美元資產頁。
沿用 DESIGN.md 與既有元件，接上現有資料契約。
顯示載入、無持倉、部分行情缺漏和錯誤狀態。
使用者資產與報價以真實 API 資料為準；開發 fixture 需與正式程式分開。
完成後提供本機預覽、手機檢查、測試與建置結果。
```

大幅改版或新的品牌風格，需要另外確認方向。已有證券工作台的設計約束，應清楚寫入提示詞和長期文件。

## 8. 24 個指令：什麼時候用

以下都以 **Codex 聊天中的 `$impeccable 指令 目標`** 使用。

| 指令 | 適合處理的問題 | 美股網站範例 |
|---|---|---|
| `init` | 產品背景未整理 | 建立使用者、流程與資料約束 |
| `document` | 設計規則未記錄 | 從現有 CSS 與元件整理 DESIGN.md |
| `shape` | 功能存在但流程尚不清楚 | 規劃持倉頁的資訊與操作路徑 |
| `critique` | 想知道整體體驗哪裡值得改善 | 評估工作台是否容易快速判斷 |
| `audit` | 要查技術品質與可用性 | 表單、對比、焦點、響應式與效能 |
| `typeset` | 字體層級與可讀性不足 | 價格、數字欄位、分析段落 |
| `layout` | 排列、間距與分組不清楚 | K 線、報價與操作區的關係 |
| `colorize` | 顏色缺少清楚用途 | 區分漲跌、警示與主要操作 |
| `bolder` | 重要元素存在感不足 | 強化主要價格與分析結論 |
| `quieter` | 太多元素同時爭取注意 | 收斂裝飾、陰影與次要標籤 |
| `distill` | 資訊或操作過多 | 合併重複狀態、簡化工具列 |
| `clarify` | 文案難懂或不精確 | 說明現金、成本、延遲與缺漏 |
| `adapt` | 不同裝置使用困難 | 手機持倉表與圖表工具列 |
| `harden` | 只有理想情境能正常使用 | 長代碼、錯誤、空值與重新送出 |
| `optimize` | 實際載入或互動偏慢 | 圖表更新、資料請求與重繪 |
| `onboard` | 首次使用者不知道怎麼開始 | 先填現金、再加入既有持倉 |
| `animate` | 操作回饋或狀態轉換不清楚 | 儲存中、完成與展開收合 |
| `delight` | 希望加入適量品牌細節 | 成功記帳的簡潔回饋 |
| `overdrive` | 需要高表現力的視覺效果 | 適合特別展示頁，工作台需審慎使用 |
| `extract` | 重複樣式開始分歧 | 抽出共用按鈕、輸入框與表格規則 |
| `polish` | 主要問題已解決，準備交付 | 對齊、邊界、互動與狀態最後打磨 |
| `live` | 想在本機瀏覽器選元素比較方向 | 選中分析摘要區作互動迭代 |
| `generate` | 想比較同一個元素的少量變體 | 比較三種分析摘要版型 |
| `craft` | 舊的建立頁面入口 | 本版已標示為棄用別名，直接描述建立需求即可 |

另外有 `doctor`、`hooks` 等管理入口，用於檢查安裝、背景文件及 hook 狀態。它們屬於管理工具，不計入上表的 24 個設計指令。

## 9. 一個好的提示詞要交代六件事

| 欄位 | 要寫什麼 | 範例 |
|---|---|---|
| 目標 | 使用者要更容易完成什麼？ | 五秒內找到現金與最大持倉 |
| 範圍 | 要改哪個頁面或元件？ | PortfolioView.tsx 的資產摘要 |
| 方向 | 有哪些既定視覺與品牌約束？ | 深色券商工作台、資訊密集 |
| 保留內容 | 哪些產品事實與行為要維持？ | 財務數字、資料契約、交易計算 |
| 狀態 | 哪些真實情境必須處理？ | 載入、無持倉、部分行情缺漏 |
| 驗收 | 怎樣算完成？ | 390px 可用、鍵盤可操作、測試與建置通過 |

你可以把「有質感」換成可檢查的要求：

```text
$impeccable layout 我的資產頁

請讓現金、持倉市值與損益形成清楚的閱讀順序。
保留目前深色券商風格及資料密度，用對齊、間距與分隔建立層級。
主要數字採一致的小數位與定位；次要說明有足夠對比。
桌面能比較多隻持倉，手機能清楚辨認股票、數量、成本與損益。
請先說明方案，再完成該範圍的修改與驗證。
```

## 10. 套用到你的五個重點區域

### 10.1 看盤與報價

優先檢查價格、漲跌、交易時段與資料時間的層級；不同長度的股票名稱和大數字也要能容納。

```text
$impeccable polish 股票報價區
請改善數字對齊、字重、間距及休市／延遲標示的清晰度。
保留漲綠跌紅規則，所有價格、日期與狀態必須對應真實資料。
```

### 10.2 K 線與技術指標

優先檢查圖表可用面積、時間範圍切換、標籤可讀性、手機橫向手勢和更新時的穩定性。

```text
$impeccable adapt src/StockChart.tsx 和圖表工具列
請驗證 1440px、1024px 和 390px 的顯示與操作。
圖表內容及指標計算保持一致，改善工具列排列、觸控操作與資料不足狀態。
請交代哪些檢查用瀏覽器模擬、哪些手勢仍需要實機驗證。
```

### 10.3 投資分析報告

閱讀順序建議是結論、理由、風險、參考價位、配置條件、完整證據。視覺強調應與資訊可靠程度一致。

```text
$impeccable layout src/AnalysisPanel.tsx
讓使用者先讀懂結論、理由與風險，再展開細節和來源。
保留來源日期、缺漏標示、費用輸入與倉位計算條件。
針對長篇報告、資料不足和分析失敗狀態一起驗證。
```

### 10.4 入金與交易表單

重點是理解、校對與回復操作：金額單位、首次現金與既有持倉的差別、費用、儲存結果和錯誤訊息。

```text
$impeccable harden src/TransactionModal.tsx
請改善標籤、說明、焦點管理、手機鍵盤和錯誤回饋。
驗證現金不足、股數不足、重複送出、費用格式錯誤與後端未連線。
沿用現有帳本計算與防重複邏輯；若發現行為缺陷，分開說明原因與修正。
```

### 10.5 新使用者的第一個畫面

沒有資料時，應清楚引導第一步。使用者填的是目前可用美元；既有股票另外記錄，避免重複扣減。

```text
$impeccable onboard 我的資產頁第一次使用流程
讓使用者知道先輸入目前可用美元，再加入既有持倉。
完成後清楚顯示已保存什麼、下一步能做什麼。
所有示例與真實資產分開，帳本尚未連接時提供準確狀態。
```

## 11. 把所有重要狀態一起設計

| 情境 | 介面應說明什麼 | 驗收重點 |
|---|---|---|
| 資料載入 | 目前正在取得哪一部分資料 | 版面穩定，必要操作有明確狀態 |
| 尚無持倉 | 下一步填什麼 | 引導現金與既有持倉，不填假資產 |
| 後端未連接 | 哪些操作尚不可用 | 儲存與模型工作清楚停用 |
| 行情限流／斷線 | 來源狀態與報價時間 | 舊報價有標示，重新整理有合理節奏 |
| 盤前／盤後／休市 | 時段及價格基準 | 色彩和文案一致，時間區域清楚 |
| 分析排隊 | 等待哪個執行端 | 知道 Mac 是否在線及工作狀態 |
| 資料不足 | 哪些證據缺漏 | 沒有用視覺把未知包裝成確定建議 |
| 表單錯誤 | 哪個欄位、如何修正 | 保留輸入，焦點與訊息可被讀取 |
| 操作成功 | 儲存了什麼 | 現金、持倉與交易紀錄一致更新 |

這些狀態同時影響美感與信任，值得在修改版面時一起檢查。

## 12. 如何審查成果

### 12.1 看實際畫面

至少檢查桌面約 1440px、較窄桌面約 1024px，以及手機約 390px。必要時補 320px，檢查最窄情況。

- 重要數字與操作是否容易找到？
- 表格是否維持正確欄位關係？需要橫向捲動時，是否只在表格區捲動？
- 繁體中文、長公司名稱、大金額及負數是否正確換行？
- 鍵盤能否進出選單、對話框與表單？焦點是否看得見？
- 文字放大至 200% 後，內容與操作是否仍能使用？
- 手機的點擊、滑動、展開與返回是否實際可操作？

瀏覽器縮成手機寬度主要驗證版面；觸控手勢與實機閱讀仍應另外檢查。

### 12.2 跑工具檢查

在 Terminal：

```bash
npx --no-install impeccable detect src/
npx --no-install impeccable detect --list-rules
```

掃描本機可見頁面，能檢查部分需要實際渲染的規則：

```bash
npx --no-install impeccable detect http://localhost:5173
```

若本機沒有可用瀏覽器，可依 CLI 提示安裝 Chrome／Chromium／Edge，或以 `IMPECCABLE_BROWSER` 指定已安裝的執行檔。雲端環境對正式網址可能有網域限制；本機預覽更適合修改與比較。

Detector 的結束碼：

| 結束碼 | 含意 |
|---|---|
| `0` | 掃描完成，沒有主要規則發現；仍可能有 advisory |
| `1` | 至少一個目標未成功掃描，應先處理工具或目標問題 |
| `2` | 掃描完成，有需要檢查的主要發現 |

原始碼掃描與渲染後掃描能看到的問題不同。沒有報告項目，不能直接推論介面品質、無障礙或產品行為已全部合格。

### 12.3 檢查產品行為

設計調整後，在 Terminal 執行：

```bash
npm test
npm run build
```

再操作與本次修改相關的流程。例如修改交易視窗，就實際測試輸入、費用、現金不足與重複提交；修改圖表，就檢查縮放、切換期間與更新狀態。測試使用開發資料，完成後清理自己的測試紀錄。

## 13. 如何理解設計評分和提醒

Impeccable 的分數與 detector 提醒，是改善的起點。請讓 Codex 對每一項說明：

1. 問題出現在什麼地方？
2. 有什麼畫面、程式或操作證據？
3. 對使用者的影響是什麼？
4. 怎麼修正，會影響哪些地方？
5. 修改後如何驗證？

你的網站刻意採用資訊密集的證券工作台。若工具對卡片、色彩或密度提出風格提醒，應根據產品背景判斷；字級、對比和操作尺寸仍需維持可用。需要例外時，記錄具體元素與原因，避免為了取得好分數而廣泛關閉規則。

本版 `audit` 會用 P0 至 P3 表示嚴重程度：P0 優先處理阻擋任務的問題，P1 處理重大可用性問題，再安排 P2、P3 的改善。評分不表示投資策略績效或財務計算已獲驗證。

## 14. 進階：比較方案與 Live 模式

你不確定一種排法是否適合時，可以先比較少量變體：

```text
$impeccable generate 3 分析摘要區的版型
比較目標是結論、理由與風險的閱讀效率。
沿用證券工作台風格，保持相同內容和功能，提出差異與適用情境。
```

若要在瀏覽器直接選元素：

```text
$impeccable live 本機股票詳情頁
請只連接本機開發伺服器，讓我選擇分析摘要區。
啟動 live 服務時設定 IMPECCABLE_LIVE_COPY_AGENT=chat，讓套用修改留在本次聊天協作。
先提供少量變體預覽，再依我的選擇修改來源。
```

Live 是進階的本機工具。請保持在本地 checkout，不要把 overlay 注入正式 Pages，也不要為此降低正式網站的內容安全設定。

本版官方文件說明：Live 的 Apply 在找不到近期聊天輪詢時，預設可能啟動本機 Codex／Claude 子程序並關閉其批准與 sandbox 保護。因此上述範例明確使用 `IMPECCABLE_LIVE_COPY_AGENT=chat`；若要完全關閉 Apply，可由啟動服務的環境設定為 `off`。在另一個 Terminal 做 `export`，不會改變已開啟的 Codex 桌面程式環境，應確認真正啟動 live 服務的程序收到設定。

一般的 critique、排版改善與本機預覽，已足以完成多數工作台改進，不必先使用 Live。

## 15. 最後打磨與發布

當主要版面、狀態及行為已經通過檢查，再使用：

```text
$impeccable polish 本輪修改的股票詳情頁
以已確認的 DESIGN.md 為準，完成對齊、間距、字體、焦點和狀態細節。
保留目前的產品內容與資料行為，檢查桌面、手機及錯誤狀態。
```

發布前：

```bash
git status --short
git diff
npm test
npm run build
```

檢查只包含本次預期的檔案，並確認沒有私人資產、金鑰、日誌或截圖被加入 Git，再提交：

```bash
git add 你已檢查的檔案
git commit -m "Improve stock detail typography and layout"
```

在已授權發布的流程中推送到 `main`，Website workflow 會測試、建置並更新同一個 GitHub Pages 站點。最後在 Actions 確認該版本發布成功，再開正式網址檢查資源與功能。快取、部署失敗和後端連接狀態，要依實際結果分開判讀。

## 16. 常見問題

### Codex 找不到 `$impeccable`

確認 `.agents/skills/impeccable/SKILL.md` 存在，專案已同步，並開啟新的 Codex 工作階段。Terminal 可用的 `npx impeccable` 不代表目前聊天已重新載入 skill。

### CLI 找不到套件

在專案根目錄執行 `npm ci`，再用 `npx --no-install impeccable --version` 檢查。使用 `--no-install` 可避免不小心臨時下載另一個版本。

### 顯示引擎下載或 checksum 錯誤

先檢查訊息中的下載來源、網路限制與套件版本，保留 TLS 與 checksum 檢查。不要把未知檔案改名為引擎，或修改預期雜湊來強行通過。若雲端家目錄不可寫，可為單次工具指令指定專案的快取位置，例如：

```bash
IMPECCABLE_HOME="$PWD/.local/impeccable/home" npx --no-install impeccable --help
```

官方來源與目前版本都已記錄在 `config/impeccable-install.json`，排查時可用來比對。

### hook 已安裝，但沒有自動提醒

Codex 可能尚未載入或信任專案 hook。先重新載入專案，依 `/hooks` 的介面確認。也可在 Codex 聊天中使用 `$impeccable hooks status`，或在 Terminal 執行：

```bash
.agents/skills/impeccable/scripts/impeccable hooks status
```

Hook 會執行程式並繼承執行環境權限，不能把它描述為已在 sandbox 中隔離。首次核准前，可檢視 `.codex/hooks.json` 與其指向的官方 launcher。

### 想知道哪些背景文件或安裝設定過時

在 Codex 聊天中使用 `$impeccable doctor`。先閱讀診斷結果，將需要修正的範圍說清楚；診斷與實際修復應分別確認。

### 想升級 Impeccable

本專案目前固定 CLI 4.8.0，並提交相同版本的 skill。升級時一起確認套件、技能與引擎相容性，閱讀官方變更內容，再跑相應檢查與 Git diff。Terminal 的 `npx --no-install impeccable update` 會檢查並更新 skill，但不等於 `package.json` 的 CLI 固定版本也已同步升級。

### 網站介面已改善，行情或儲存仍不能使用

先看頁面的 API 連線、資料來源與 Mac 狀態。GitHub Pages 提供靜態前端；雲端帳本、Yahoo 代理和 Mac 工作佇列需要另外接上的後端。把功能連接問題與設計品質問題分別追蹤。

## 17. 可以直接貼給 Codex 的完整任務

以下範例適合開始改善你目前的網站：

```text
請使用 Impeccable 改善 Northstar 的股票詳情頁。

產品：個人美股研究工作台，主要查看大型美股、一般 ETF、美元持倉和投資分析。
視覺：沿用深色證券平台風格，以清楚的資訊密度、數字對齊、字體層級與穩定互動展現質感。

請先讀 AGENTS.md、PRODUCT.md、DESIGN.md；缺少背景時先從現有文件與程式碼整理，只詢問無法推斷的關鍵事項。

流程：
1. 檢查本機可執行的畫面，對這個範圍做 critique 與 audit。
2. 先呈現三項最值得改善的問題、證據、預計影響與方案。
3. 依我選擇的方案，分輪處理 typeset、layout、adapt、harden，再做 polish。
4. 每輪保留投資文字、資料來源、財務計算和既有功能，將新的產品決策分開提出。
5. 行情、報告與本金以實際資料狀態呈現；開發 fixture 只用於有標示的測試。
6. 驗證 1440px、1024px、390px、鍵盤操作與重要錯誤情境。
7. 跑相關測試與正式建置，檢查差異，每個邏輯更新建立 Git commit。
8. 已授權發布時更新既有 GitHub Pages 網址，並報告實際發布結果與尚未驗證的功能。

這一輪先做第 1、2 步。
```
